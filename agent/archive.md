# Agent 工作档案

任务档案规则，与《Agent 工作守则》配套：工作过程全部落入档案，任何新会话只读档案即可接手。

## 目录结构

```
docs/
  lessons.md               # 跨任务沉淀，长期活文档
  tasks/
    2026-09-25-task-slug/  # 目录名：日期 + 英文短名（kebab-case）
      README.md            # 任务档案：状态、时间线、决策记录
      explore/             # 探索产物，自由命名
      define/              # plan.md（入口）
      execute/             # deliverable.md（入口）
      review/              # verdict.md（入口）
```

## 建档

1. 档案建在当前工作仓库的 `docs/tasks/` 下，一个任务一个目录，目录名 = `日期-英文短名`，kebab-case。
2. 所有路径（目录名、文件名）一律英文；文件内容语言不限。
3. `README.md` 是唯一活文档：当前阶段、时间线、关键决策，每完成一个阶段更新。
4. 阶段文件夹在产生第一个文件时创建，不预建空目录。

## 归档

5. 产物放所属阶段：探索的笔记、对比、一次性代码 → `explore/`；计划 → `define/plan.md`；交付说明 → `execute/deliverable.md`；验收结论 → `review/verdict.md`。入口文件可从 `templates/` 复制。
6. `define/`、`execute/`、`review/` 各只有一个入口文件；入口之外可自由增加文件（子计划、日志、截图、复检记录），附件放所属阶段文件夹内。
7. `explore/` 是耗材区：允许乱、可随时清空、其中代码不是正式实现，不得被正式实现引用。

## 交接

8. 文档即交接：会话中的判断和决定必须写入任务目录，没有写入的视为没有发生。
9. 目录即上下文：新会话接手时先读 `README.md`，再按需读入口文件；读档案接不上手，先补档案再继续。
10. `deliverable.md` 清单（与守则一致）：改动摘要、验证结果、不确定点、决策记录、重点验收项、最短验收路径。
11. `verdict.md` 只写三种结论：`PASS`；`FAIL`（证据 + 返回哪个阶段）；`HUMAN_DECISION_REQUIRED`（问题和选项）。

## 经验与清理

12. 经验回填：验收时产生的跨任务教训写入 `docs/lessons.md`；只对本任务有意义的留在任务目录。
13. 任务 `PASS` 后可清空 `explore/`；任务目录永不删除，它是观察指标的原始数据。
