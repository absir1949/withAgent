# withAgent

一套人与 Agent 协作工作的开源方法论。

## 背景

Agent 已经可以独立工作几十分钟甚至数小时。但大多数人的协作方式仍然是「实时聊天式」的：任务完成要看一眼、有问题要马上答、看完了忍不住当场改——每一次都在打断人。

新的瓶颈不再是机器的执行速度，而是**人的注意力与判断**。

这套方法论的核心主张是：工作方式需要从「人与 Agent 实时来回协作」，转向「**人集中判断，机器异步执行**」。目标是让每一单位稀缺的人类判断，撬动尽可能多的有效机器劳动。

## 文档

三份文档，分别回答三个层面的问题，建议按顺序阅读：

| 文档 | 回答的问题 |
|---|---|
| [Agent 时代的工作哲学](Agent%20时代的工作哲学.md) | **为什么**这样工作 —— 目标函数与四条核心原则 |
| [Agent 工作协议](Agent%20工作协议.md) | **人**怎么工作 —— 状态、交接接口、批次与流水线 |
| [Agent 工作守则](Agent%20工作守则.md) | **Agent** 怎么工作 —— 四阶段行为规则 |

三者的关系：

- **哲学**给出目标函数和四条核心原则：价值主权、探索购买信息、反馈闭环、认知背压；
- **协议**把原则落成人的工作制度：探索 → 定义 → 执行 → 验收四种状态，「计划 / 交付物」两个交接接口，批次验收，用验收能力限制并发；
- **守则**是给 Agent 的行为规范：`EXPLORE → DEFINE → EXECUTE → REVIEW` 四阶段，可直接用于你的 Agent 配置。

## 如何使用

**人的这一侧**：按协议组织工作节奏——探索和定义 → 批量下发 → 执行期间不看 → 固定窗口集中验收 → 验收只形成判断，失败项进入下一轮。

**Agent 的这一侧**：把[《Agent 工作守则》](Agent%20工作守则.md)放进你的 Agent 配置（如 `AGENTS.md`、`CLAUDE.md` 等），让 Agent 按四阶段自主工作、自行验证、按标准格式交付。

## 版本与迭代

- 每篇文档独立演进，版本号标注在文末。
- 当前均为 **v0.1**，是最小可用版本，会在真实使用中持续迭代。
- 协议中定义了观察指标（一次验收通过率、返工轮数、中途阻塞次数、验收耗时），后续迭代依据来自真实运行数据，而不是想象。
